# Manage Iteration

## Purpose

Centralize every iteration-number operation. The iteration identifier format is `v{major}.{minor}`; see AGENTS.md §17 for the full versioning rules.

1. **Detect the next iteration number**: scan existing `v{major}.{minor}/` directories under `iteration/` and return the next consecutive pair.
2. **Create a new iteration skeleton**: create the five empty delivery-stage subdirectories under `iteration/v{major}.{minor}/`; raw user requirements are stored centrally under `iteration/raw-requirement/`.
3. **Archive a finished iteration**: after the next consecutive version's skeleton is created successfully and the instance root `README.md` has merged the RC-complete predecessor's functionality into the current system-functionality section, move the predecessor wholesale to `iteration/archive/v{major}.{minor}/` and record the archive time.
4. **Resolve the active iteration**: return the latest Approved iteration number for use by other skills.

## Path Conventions

```text
Project Root
├── iteration/
│   ├── v1.0/                                ← currently active
│   ├── v1.1/                                ← currently active
│   └── archive/
│       └── v1.0/                            ← RC-complete snapshot
```

## Operations

### 0. Initialize Project and Version

```powershell
python .aw/.workflow/workflow.py init
python .aw/.workflow/workflow.py init-version
```

`init` creates `baseline/raw-requirement/`, `iteration/raw-requirement/`, `iteration/`, and `workspace/`, and writes the workflow-entry explanatory files. Use `archive-requirement --source <file>` to place input into an immutable `intake-<name>/` batch and record it in `workspace/workflow/raw-requirement-index.yaml`. `workspace/README.md` is created and maintained by the instance project itself: it only explains how the workspace works and is not generated by the workflow to carry current-version functionality. The instance root `README.md` is instance-owned; after `05-review-release` passes, the workflow rebuilds its current-system-functionality section from the cumulative approved FR/BR requirements, current functional changes, and current release-log limits. `iteration/raw-requirement/README.md` is the only explanatory file in that directory; everything else in it is raw user material. `init` applies to projects that have not yet started and does not create any version directory.

`init-version` may create the next consecutive version's directory skeleton only after `validate --stage 00-baseline` passes, and refreshes the manifest automatically. The first version is `v1.0`; it creates only the five formal stage directories and creates or approves no artifacts. Before any later version is created, the active predecessor must pass `validate --stage 05-review-release`; that gate regenerates the instance root README from the complete approved FR/BR history and current-version release-log limits, without a separate README approval. `init-version` revalidates the predecessor and checks the rendered README content before archiving; if the refresh check fails, it removes only the empty successor skeleton and leaves the predecessor and archive unchanged.

### 1. Detect Next Version

Scan the `v{major}.{minor}/` directory names under `iteration/` and return the next consecutive version number.

```python
import re
from pathlib import Path

def next_version(iteration_dir: Path) -> str:
    """Return the next iteration id given existing v{major}.{minor} directories.

    Bumps the minor when current major matches the highest seen; otherwise
    starts a new major at `.0`.
    """
    pattern = re.compile(r"v(\d+)(?:\.(\d+))?$")
    pairs: list[tuple[int, int]] = []
    for p in iteration_dir.iterdir():
        if not p.is_dir():
            continue
        m = pattern.match(p.name)
        if m:
            pairs.append((int(m.group(1)), int(m.group(2) or 0)))
    if not pairs:
        return "v1.0"
    pairs.sort()
    major, minor = pairs[-1]
    # Decision rule: bump minor by 1. Promote to (major+1, 0) only when the
    # caller explicitly signals a baseline shift; default behavior stays in-major.
    return f"v{major}.{minor + 1}"
```

`next_version` MUST NOT return `v1.0` when `stage-gate` has not passed for `00-baseline`; the baseline review must succeed first.

### 2. Create New Version Skeleton

```text
iteration/v{major}.{minor}/
├── 01-product/
├── 02-design/
├── 03-planning/
├── 04-implementation/
└── 05-review-release/
```

Create empty directories only; place no files inside. Raw user requirements are stored centrally in `iteration/raw-requirement/intake-<name>/` in their original format and original wording; that directory is the input for `normalize-requirement` and does not require `status: Approved`. Run `route-requirement` first, then pass its target version to `archive-requirement --source <file> --iteration <target-version>`; the raw files are read-only, and agents MUST NOT modify, rename, or delete them.

### 3. Archive Previous Version

Trigger: after the next consecutive version's skeleton has been created successfully. The predecessor being archived MUST have already passed `validate --stage 05-review-release`; its release artifact records the review, merge, release decision, and release notes.

Execution steps:

1. Create the next consecutive version's five stage directories; if this step fails, do not archive.
2. Create the `iteration/archive/v{major}.{minor}/` directory for the predecessor.
3. Move **all content** under `iteration/v{major}.{minor}/` into `iteration/archive/v{major}.{minor}/`.
4. Write the archive metadata into `iteration/archive/v{major}.{minor}/ARCHIVED.md`:

```text
# Archive: v{major}.{minor}

- archived_at: YYYY-MM-DD
- superseded_by: v{next_major}.{next_minor}
- rc_artifact: iteration/v{major}.{minor}/05-review-release/v{major}.{minor}-review-release.md
- release_log: iteration/v{major}.{minor}/05-review-release/v{major}.{minor}-release-log.md  (reference)
- note: this directory is read-only; do not modify.
```

5. Do not delete the archived version's release log; the archive directory is a read-only snapshot.

#### Instance README refresh

The generated instance root `README.md` MUST show the target version's product name, product overview, complete module-level current capability summaries, and user-visible limits. The target Approved product requirement MUST contain a complete `README 模块摘要` catalog with each active FR/BR covered exactly once. The README contains no per-requirement list, workflow instructions, or HTML markers. The target version is shown as reader-facing text.

The CLI replays approved FR/BR history to validate module coverage, then atomically replaces the whole root README after 05-review-release passes. Missing, duplicate, unknown, or deprecated coverage blocks generation without changing the file. No separate README approval is added. Freshness compares the complete expected file, and `init-version` reruns validation before archiving; any replay or content error blocks the archive.

### 4. Resolve Current Active Version

Return the latest **Approved** iteration number:

1. Read the frontmatter `status` of every `iteration/v{major}.{minor}/05-review-release/v{major}.{minor}-review-release.md` under `iteration/`.
2. Sort descending by `(major, minor)` and find the first iteration with `status: Approved`.
3. If none is Approved, return the iteration with the largest `(major, minor)` (even if still draft).

## Failure Handling

- **Iteration numbers may not be skipped** (for example, forbid going from v1.0 directly to v1.2; majors may not be skipped from v1 to v3).
- **Archived iterations under `iteration/archive/` may not be overwritten.**
- **`iteration/v1.0/` may not be created** without passing the `stage-gate` `00-baseline` gate. A subsequent upgrade MUST stop when the predecessor's `05` gate has not passed, and the predecessor may not be moved.
- When a conflict is detected (for example, a `v{major}.{minor}/` directory was created manually without going through this skill), report it and request a human decision.

## Common Mistakes

| Mistake | Correction |
|---|---|
| Directly `mkdir iteration/v1.1/` without invoking this skill | Use manage-iteration so the references and archive chain stay complete. |
| Archive the predecessor but forget to write the release log | Prompt the user: `v{major}.{minor}-release-log.md` must exist (it is required to exist before `05-review-release` passes; no extra write is needed before archive). |
| Manually edit files under `iteration/archive/v{major}.{minor}/` | Block; if a correction is needed, open a new iteration. |
Instance documentation ownership: `AGENTS.md` and root `README.md` are created during initialization and then remain instance-owned; `sync` updates only `.aw/README.md` and other workflow files. The root README is fully regenerated after 05-review-release from the target Approved requirement's complete module summary catalog and user-visible release-log limits; `workspace/README.md` remains static workspace guidance.

This ownership rule supersedes any earlier wording in this skill that describes the root README as framework-owned.
